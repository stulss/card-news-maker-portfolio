"Canva의 무거운 기능 중 카드뉴스 제작 흐름에 꼭 필요한 본질만 골라 프론트엔드로 구현했습니다."

🛡️
PILLAR 01 · COMPLETE CLIENT-SIDE PRIVACY

서버 0원 & 사용자 이미지 유출 0% (IndexedDB 아키텍처)

사용자가 업로드한 고용량 사진과 스티커는 외부 서버로 1바이트도 전송되지 않습니다. `blob:` URL의 세션 종료 시 휘발성 한계와 `localStorage`의 엄격한 용량 상한(~5MB)을 극복하기 위해, IndexedDB 기반 무제한 덱 저장소(deckStore)를 구축했습니다. JSON 스키마 방어 검증기를 거쳐 손상된 데이터가 주입되어도 안전하게 기본값으로 복구합니다.

// IndexedDB 자동 저장 및 Data URL 변환 캐싱 export async function saveDeckToIndexedDB(deck: Deck): Promise<void> { const serialized = await serializeDeckWithImages(deck); const db = await openDatabase(); await db.put('decks', serialized, 'current_deck'); }
📐
PILLAR 02 · ZERO RENDERING DRIFT

미리보기 = 내보내기 1:1 무결점 파이프라인

HTML2Canvas 등 서드파티 캡처 라이브러리는 CSS 그림자나 회전 변형 시 화면과 결과물이 달라지는 고질병이 있습니다. 카드툰은 미리보기 화면과 고해상도 내보내기 파이프라인이 단 하나의 Konva Stage 객체를 공유하여 1픽셀, 0.1도 회전각도 어긋나지 않는 100% 무결점 출력을 보증합니다.

const stage = stageRef.current; await waitForImagesAndFontsLoaded(stage); const dataUrl = stage.toDataURL({ pixelRatio: exportScale });
⏮️
PILLAR 03 · IMMUTABLE HISTORY ENGINE

불변 상태 기반 지능형 되돌리기 (Undo/Redo)

과거 레이어의 `zIndex`를 제자리(in-place) 수정하던 레거시 구조를 완전한 불변(Immutable) 상태 트리로 리팩토링했습니다. 사용자가 투명도나 크기 슬라이더를 5번 연속 조작할 때는 디바운스 병합(Coalescing)을 통해 1단계로 묶고, 레이어 추가/삭제나 방향키 이동은 각각 독립 단계로 보존하는 지능형 이력 스택을 완성했습니다.

// 슬라이더 연속 변경은 타임스탬프 기반 순수 상태 병합 if (action.type === 'UPDATE' && last?.type === action.type && Date.now() - last.time < 400) { return { ...state, present: action.payload }; // 병합 }
🤖
PILLAR 04 · IN-BROWSER WASM AI

브라우저 내 WASM AI 배경 제거 & CSP 방어

서버 API를 호출하지 않고 클라이언트 WebAssembly(ONNX Runtime Web) 기반으로 이미지 누끼를 실시간 분리합니다. 운영 환경에서 발생했던 엄격한 Content Security Policy(CSP)의 `blob:` 스크립트 모듈 차단 결함을 `worker-src blob:` 및 `script-src` 보안 헤더 세밀 조율로 해결하여 상용화 보안과 AI 기능을 양립시켰습니다.

// vercel.json 보안 헤더와 blob: 워커 공존 설계 "Content-Security-Policy": "script-src 'self' 'unsafe-eval' blob:; worker-src 'self' blob:;"

01

되돌리기를 넣었더니 레이어 순서 변경이 과거 이력 스냅샷까지 훼손한 사건

불변성 붕괴 방어
상태 관리
S · SITUATION

레이어 순서를 ▲▼ 버튼으로 변경한 뒤 Ctrl+Z(실행 취소)를 눌렀을 때, 과거 스냅샷의 zIndex가 이미 바뀌어 있어 이전 상태로 복구되지 않는 잠재적 데이터 오염 현상 발생.

T · TASK

과거 스냅샷과 현재 작업 상태가 동일한 메모리 객체 레퍼런스를 공유하는 문제를 완전히 차단하고 엄격한 불변 트리 확립.

A · ACTION

기존의 `layer.zIndex = newZ` 제자리(in-place) 수정 코드를 전면 폐기하고, `reorderLayers` 함수가 항상 새 배열과 새 레이어 복사본을 반환하도록 리팩토링.

R · RESULT

레이어 이동, 그룹 묶기, 정렬 등 모든 상태 변경이 불변 스냅샷으로 격리되어 100회 이상의 연속 Undo/Redo 스트레스 테스트에서 오작동 0건 달성.

💡 Insight: 스냅샷 기반의 이력 시스템을 도입할 때는 객체 내부를 제자리에서 수정하는 코드를 전수 조사하여 완전한 불변 복제로 전환해야 한다.
02

새 웹폰트를 골라도 캔버스 글자가 바뀌지 않던 비동기 폰트 로딩 결함

캔버스 라이프사이클
렌더링 파이프라인
S · SITUATION

글꼴 드롭다운에서 한글 웹폰트(예: "주아", "도현")를 선택해도 캔버스 글자가 시스템 기본 폰트(맑은 고딕)로 조용히 폴백되는 현상.

T · TASK

웹폰트 다운로드가 완료되는 즉시 캔버스 노드를 강제 재렌더링하여 선택한 글꼴이 누락 없이 100% 반영되도록 보장.

A · ACTION

캔버스(HTML5 Canvas)는 DOM과 달리 아직 쓰이지 않은 웹폰트를 스스로 페칭하지 않는 특성 확인. `document.fonts.load(16px FontName)`로 브라우저에 폰트를 명시적으로 페칭한 후 캔버스를 재호출하는 `fontKey` 동기화 훅 구현.

R · RESULT

12종 자체 호스팅 한글 폰트 전 구간에서 폰트 미적용 0건. 고해상도 내보내기 시에도 폰트 깨짐 현상 원천 차단.

💡 Insight: 캔버스에 그리는 폰트는 단순 "CSS 선언"이 아니라 "네트워크 로드 완료(document.fonts.ready)" 시점을 반드시 감지해야 한다.
03

운영 환경 CSP(Content Security Policy)가 WASM AI 배경 제거를 차단한 이슈

보안 아키텍처
WASM & CSP
S · SITUATION

로컬 개발 서버에서는 완벽히 작동하던 AI 배경 제거가 Vercel 운영 빌드에서 `Failed to fetch dynamically imported module: blob:...` 에러를 뿜으며 조용히 실패.

T · TASK

웹 취약점 방어를 위한 엄격한 CSP 헤더를 유지하면서도 Transformers.js / ONNX Runtime이 생성하는 blob 워커를 안전하게 실행.

A · ACTION

WASM 로더가 `URL.createObjectURL`을 통해 동적 blob 스크립트를 로드하는 구조 분석. `vercel.json`의 보안 헤더에서 `script-src 'self' 'unsafe-eval' blob:` 및 `worker-src 'self' blob:`을 정밀 허용.

R · RESULT

운영 환경에서도 브라우저 내 AI 누끼 따기 100% 정상 작동. 상용화 보안 헤더(X-Frame-Options, X-Content-Type-Options 등)와 기능성 양립 달성.

💡 Insight: 최신 클라이언트 사이드 AI/WASM 라이브러리는 내부적으로 동적 blob 워커를 적극 활용하므로 운영 보안 헤더(CSP)와의 정밀한 조율이 필수적이다.
04

다중 슬라이드 캐러셀(10장) 일괄 내보내기 시 비동기 이미지 누락 방지

비동기 렌더링 락
대량 내보내기
S · SITUATION

10장의 카드뉴스를 ZIP 파일로 한 번에 내보낼 때, 슬라이드가 고속으로 전환되면서 특정 장에서 이미지가 미처 로드되지 않아 빈 캔버스가 캡처되는 결함.

T · TASK

각 슬라이드의 모든 이미지 노드가 GPU에 바인딩되고 폰트 로딩이 완료될 때까지 정확히 대기하는 비동기 동기화 락(Lock) 설계.

A · ACTION

`CanvasStage`에 `isReady()` 프로미스 게이트웨이를 노출. 슬라이드 변경 후 화면 내 이미지 엘리먼트의 `complete` 상태와 폰트 로드를 전수 확인한 뒤에만 `toDataURL`을 호출하고 진행률 프로그레스바로 사용자 피드백 제공.

R · RESULT

10장 연속 고해상도 ZIP 내보내기 시 이미지 누락률 0%. 인스타그램 10장 세트 원클릭 패키징 안정성 확보.

💡 Insight: 캔버스 일괄 내보내기는 '루프 속도'보다 '렌더링 완료 상태 확인(State Readiness)'이 품질을 결정한다.
05

모바일 터치 환경에서 레이어 드래그 앤 드롭 정렬 미동작 해결

터치 인터랙션
크로스 디바이스
S · SITUATION

데스크탑에서는 마우스로 잘 되던 레이어 순서 변경(⋮⋮ 드래그)이 모바일 스마트폰 화면에서는 터치 시 스크롤만 발생하고 전혀 동작하지 않음.

T · TASK

마우스와 터치스크린 입력 모두에서 100% 동일하게 부드럽게 작동하는 통합 포인터 드래그 핸들러 구현.

A · ACTION

HTML5 Drag & Drop API가 모바일 터치 이벤트를 지원하지 않는 점을 파악하고, 최신 Pointer Events (`setPointerCapture` + `document.elementFromPoint`) 파이프라인으로 전면 개편. CSS에 `touch-action: none` 부여.

R · RESULT

아이폰 Safari, 안드로이드 Chrome 등 모바일 환경에서도 손가락 터치 드래그로 레이어 순서 변경 완벽 지원.

💡 Insight: 모바일 웹 그래픽 에디터에서는 HTML5 DnD 대신 Pointer Events를 기본 표준으로 채택해야 한다.
06

새로고침 시 업로드했던 이미지가 소실되는 브라우저 메모리 한계 극복

데이터 지속성
IndexedDB 스토리지
S · SITUATION

사용자가 사진을 올려 카드뉴스를 만들던 중 실수로 새로고침을 누르면 업로드한 이미지가 `blob:` 세션 만료로 전부 엑박(깨짐)으로 유실됨.

T · TASK

서버를 쓰지 않으면서도 수십 MB 용량의 이미지 데이터가 브라우저를 닫거나 새로고침해도 영구 보존되도록 구현.

A · ACTION

5MB 용량 한계가 있는 localStorage 대신 IndexedDB를 도입하고, 덱 자동 저장 시점에 blob 데이터를 직렬화된 base64 Data URL로 안전하게 변환하여 캐싱.

R · RESULT

새로고침 및 브라우저 재실행 시 작업 중이던 이미지와 레이어가 0.5초 만에 100% 자동 복구. 작업 유실 불안 해소.

💡 Insight: 클라이언트 그래픽 앱에서 데이터 영속성은 사용자의 신뢰와 직결된다. 대용량 바이너리는 IndexedDB가 정답이다.
07

React 18/19 StrictMode 이중 호출로 인한 이력 병합 왜곡 해결

React 동시성
순수 함수 상태
S · SITUATION

개발 모드에서 방향키로 레이어를 이동했을 때 작업 이력에 이동 단계가 기록되지 않고 바로 앞의 추가 단계에 흡수되어 버리는 기현상.

T · TASK

React의 StrictMode 이중 렌더링 환경에서도 예측 가능하고 순수한 이력 병합 로직 구축.

A · ACTION

병합 판단용 값을 컴포넌트 외부의 `ref`에서 수정하던 것이 원인. 상태 갱신 함수 내부에서 외부 ref를 변경하면 이중 호출 시 두 번째 호출이 오염된 값을 보게 됨. 마지막 변경 키와 시각을 상태 내부(`last`)로 이동해 순수 리듀서로 전환.

R · RESULT

개발 모드와 프로덕션 빌드 간 이력 동작 100% 일치. 슬라이더 조작은 1단계로 합쳐지고 방향키 이동은 정확히 개별 단계로 기록.

💡 Insight: React 상태 갱신 함수 안에서는 절대 외부의 ref나 전역 변수를 조작하면 안 된다. 상태 갱신은 순수해야 한다.
08

Konva의 그라디언트와 단색 fill 충돌 및 8자리 hex 파싱 결함

렌더러 결함 극복
컬러 파서 방어
S · SITUATION

도형에 선형 그라디언트를 지정했는데 단색으로만 보이거나, 텍스트 그림자에 투명 hex(`#00000066`)를 넣었을 때 색상이 무시되는 버그.

T · TASK

Konva의 내부 fill 우선순위 규칙과 색상 파서의 제한을 극복하는 공용 렌더링 어댑터 구축.

A · ACTION

그라디언트 지정 시에는 `fill` 속성을 완전히 제거하고 전달하도록 분기 처리. 그림자 색상은 8자리 hex 대신 표준 `rgba(r,g,b,a)` 문자열로 변환하여 주입.

R · RESULT

배경, 사각형, 둥근 모서리 등 모든 도형에서 감성적인 다채색 그라디언트와 미세 그림자 연출 정상화.

💡 Insight: 외부 라이브러리의 렌더링 우선순위와 속성 파싱 규칙을 맹신하지 말고 방어적 정규화 계층을 두어야 한다.
