SLIDE DECK PIPELINE

인스타그램 10장 캐러셀 슬라이드 스트립

단일 캔버스 편집을 넘어 최대 10장의 슬라이드를 하단 썸네일 스트립으로 직관적으로 전환하고 복제·삭제·순서 변경을 지원합니다.

  • 규격 프리셋 전환: 1:1 정방형 피드(1080×1080), 4:5 인스타 세로형(1080×1350), 9:16 릴스/스토리 즉시 전환.
  • 페이지 번호 자동 각인: "01/05", "02/05" 워터마크가 슬라이드 추가/삭제 시 인덱스를 동적으로 자동 재연산.
  • 원클릭 ZIP 일괄 내보내기: JSZip을 통해 브라우저 메모리 상에서 10장의 고해상도 이미지를 압축하여 한 번에 다운로드.
ADVANCED TYPOGRAPHY

곡선 글자(Arc Text) & 정밀 타이포그래피

  • 수학적 원형 곡률 렌더러: 글자마다 각도(Theta)를 동적으로 계산하여 회전 변환 행렬을 적용하는 삼각함수 알고리즘.
  • 외곽선 & 그라디언트: 2중 외곽선(Stroke), 멀티스톱 컬러 그라디언트, 부드러운 그림자(Shadow Blur) 지원.
  • 자체 호스팅 폰트 동기화: 10종의 한글 폰트를 document.fonts.load() 비동기 래퍼로 캔버스 렌더링 누락 방지.

  • 완전 로컬 렌더링: 외부 QR 서비스 장애나 트래킹 URL 변조 위험이 원천 차단됩니다.

  • WCAG 명도 대비 경고: 배경색과 텍스트 색상의 대비율을 계산하여 가독성 가이드를 제공.
IMMUTABLE REDO/UNDO

단순한 Ctrl+Z를 넘어, 사용자가 수행한 작업 내역을 자연어 라벨("텍스트 색상 변경", "도형 추가")로 시각화한 히스토리 타임라인입니다.

  • 원클릭 타임슬립 복원: 과거 특정 작업 단계를 클릭하면 캔버스 상태가 해당 시점으로 즉각 롤백.
  • 슬라이더 조작 쓰로틀링: 크기나 각도를 연속 드래그할 때 500ms 디바운스로 스냅샷 폭증을 방어.
  • 불변 상태 불변성 보장: 깊은 복사 순수 함수 파이프라인으로 과거 스냅샷 오염 0건 달성.

💡 핵심 설계 철학: 왜 100% 클라이언트 온디바이스 아키텍처인가?

웹 에디터 개발 시 가장 쉬운 길은 백엔드 서버에 이미지 변환 API(Sharp, Python FastAPI 등)를 두고 캡처와 AI 연산을 위임하는 것입니다. 그러나 이 방식은 서버 트래픽 비용, 클라우드 호스팅 요금, 그리고 무엇보다 사용자의 민감한 개인 사진이 외부 네트워크로 유출되는 치명적인 프라이버시 문제를 야기합니다. 카드툰은 모든 그래픽 렌더링과 AI 연산을 브라우저 내부(WASM + Canvas 2D)로 흡수하여 서버 비용 0원, 사용자 데이터 외부 전송 0 Byte를 실현했습니다.

STEP 1
액션 디스패치 & 상태 방출

레이어 이동, 텍스트 수정 시 불변 리듀서가 새로운 불변 씬 그래프 트리를 방출합니다.

Input: Layer Action Event
STEP 2
웹폰트 로드 동기화 게이트

캔버스 특성상 누락되기 쉬운 한글 폰트를 document.fonts.load()로 비동기 검증 후 fontKey 방출.

Gate: Font Readiness Check
STEP 3
Konva Stage 리렌더링

Text, Image, Shape 노드가 씬 그래프를 최적화하여 60FPS 하드웨어 가속 캔버스에 즉각 렌더링.

Core: 60FPS Canvas Draw
STEP 4
자석 스냅 & 셰이더 필터

14px 임계치 자석 가이드라인 계산 및 WebGL 셰이더 필터(블러, 밝기, 대비) 실시간 오버레이.

Post: WebGL Filter + Snap

💡 왜 DOM 조작 대신 Konva.js 씬 그래프를 선택했는가?

일반 HTML DOM 기반 에디터는 레이어가 30~50개 이상 쌓이면 브라우저 Layout/Reflow 비용이 급격히 증가하여 프레임 드랍이 발생합니다. 반면 순수 HTML5 Canvas는 모든 도형과 텍스트를 좌표 단위 명령어로 일일이 그려야 하므로 상태 관리가 난해합니다. react-konva는 Canvas 2D 컨텍스트 위에 가상 씬 그래프를 올려 고성능 렌더링 성능과 리액트의 선언형 컴포넌트 모델을 완벽히 결합했습니다.

STEP 1
이미지 텐서 전처리

사용자 사진을 1536px 정규화 텐서 버퍼로 변환하고 메모리 누수를 방지하기 위해 단일 버퍼로 래핑.

Input: Raw Image Buffer
STEP 2
Web Worker 스레드 격리

무거운 AI 추론 연산이 브라우저 메인 스레드를 멈추게 하지 않도록 백그라운드 워커에서 독립 구동.

Thread: Offscreen Worker (0ms UI Freeze)
STEP 3
WASM MODNet 누끼 추론

@huggingface/transformers ONNX 런타임을 통해 로컬 CPU/WASM 환경에서 정밀 알파 매트를 추출.

Inference: 100% Local (0 API Cost)
STEP 4

WASM 바이너리와 ONNX 가중치는 약 27MB로 초기 번들에 포함할 경우 첫 페이지 로딩 속도(LCP)를 크게 저하시킵니다. 이를 방지하기 위해 import('./services/ai') 동적 임포트를 적용하여, 사용자가 AI 배경 제거 탭을 클릭하는 시점에만 비동기로 모듈을 다운로드하도록 설계했습니다.

💡 되돌리기(Undo) 시 객체 레퍼런스 오염 문제의 해결

초기 프로토타입에서는 레이어 순서 변경(reorderLayers) 시 객체 내부의 zIndex를 제자리에서 수정하여 과거 스냅샷과 현재 상태가 메모리 레퍼런스를 공유하는 버그가 있었습니다. 이로 인해 Undo를 실행해도 레이어 순서가 이전으로 돌아가지 않는 문제가 발생했습니다. 전수 조사를 통해 모든 배열 조작을 [...layers.map(l => ({ ...l }))] 완전 불변 복제로 리팩토링하여 100회 이상의 연속 Undo/Redo 스트레스 테스트를 완벽 통과했습니다.

STEP 1

Input: Deck Slide Iteration
STEP 2
isReady() 프로미스 배리어

Barrier: Rendezvous Readiness Gate
STEP 3
동일 Konva Stage 네이티브 캡처

별도 가상 렌더러를 띄우지 않고 화면 렌더러와 동일한 Stage에서 toDataURL() 호출.

Render: 1:1 Pixel-Perfect WYSIWYG
STEP 4
JSZip 메모리 스트림 패키징

생성된 PNG/WebP 바이너리를 브라우저 메모리 상에서 ZIP으로 압축 번들링하여 다운로드 완료.

Output: 10-Slide ZIP Stream Bundle

💡 랑데부(Rendezvous) 게이트로 빈 화면 캡처 결함 해결
